# 机壳素材与备选方案

## 本项目采用的方案

### fastlane/frameit-frames（机壳素材）

- 地址：https://github.com/fastlane/frameit-frames （gh-pages 分支）
- ★ 约 280 个机壳 PNG，其中 iPhone 17 系列 11 个变体
- 素材为透明背景 PNG，屏幕区域 alpha≈0，正是 `bezel.py` 挖孔检测的前提
- 仓库**未声明 SPDX 许可**；机壳外观源自 Apple 官方设备图
- 脚本中 `VER = "1772014847"` 是 gh-pages 的版本目录，pin 住避免上游重命名导致 404

### fastlane/fastlane（frameit 本体）

- 地址：https://github.com/fastlane/fastlane （42.3k★，MIT）
- `frameit` 是其中一个 action，**没有独立仓库**
- 依赖 Ruby + ImageMagick，装起来重；它的核心价值是「机壳素材 + 自动套壳」思路
- 本项目只取它的素材，用 Pillow 重新实现渲染，避免 Ruby 依赖

## 为什么没用别的方案

| 方案 | 问题 |
|---|---|
| frameit（Ruby） | 需要 Ruby 环境 + ImageMagick，只为了套壳太重 |
| 无头浏览器截图成图 | 启动慢、内存高，且圆角裁切不好做 |
| 手写 CSS `border-radius` 模拟 | 屏幕挖空区和真机圆角对不上，边缘会露白 |
| 在线套壳网站 | 要上传截图，隐私和批量都不方便 |

## 这套实现的关键点

1. **不硬编码圆角半径**。不同机型圆角差异很大（SE 几乎是直角，17 Pro Max 则很圆），
   所以直接用机壳挖孔区的 alpha 当蒙版，天然跟真机一致。
2. **泛洪填充而不是找 bbox**。机壳四周也是透明的，直接取全图 alpha 非零区域会把
   外围空白也算进去。从画布中心泛洪，才能只圈到屏幕那块互不连通的区域。
3. **投影降采样**。全分辨率高斯模糊是大头（6s+），1/4 分辨率模糊再放大，
   差异 0.99/255，耗时从 8.4s 降到 2.1s。
4. **渐变先小图再放大**。64×64 上插值再双三次放大，避免逐像素 Python 循环算全图。

## 素材许可注意事项

`frameit-frames` 未给 SPDX 声明，机壳外观版权属于 Apple。
自用、上架 App Store 截图一般无碍（业界普遍这么用）；
但如果要把带机壳的图作为**素材包对外分发**，请先自行确认授权，
或改用自己拍摄/绘制的设备外壳。
